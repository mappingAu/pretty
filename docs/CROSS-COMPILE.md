## Backend features and platform support

Vulkan and GLES are the default features. The `metal` feature maps to
`wgpu/metal` and `dx` maps to `wgpu/dx12`; both are compiled into the
native Windows/macOS release binaries by `.github/workflows/build.yml`.
`auto` prefers Direct3D 12 on Windows and Metal on macOS, and skips any
backend that is not compiled in. A backend that is selected but
unavailable fails with a typed error: there is no silent fallback and no
CPU rasteriser.

## Native CI builds

The Linux host that generates this report has no MinGW or Apple linker, so
the cross-target checks above are compile-only. Native release binaries are
built and unit-tested by `.github/workflows/build.yml`:

| Runner | Backend features | Artifact |
|---|---|---|
| `ubuntu-latest` | default (Vulkan + GLES) | `pretty-<ver>-linux-x86_64.tar.gz` |
| `windows-latest` | `--features dx` | `pretty-<ver>-windows-x86_64.zip` |
| `macos-latest` | `--features metal` | `pretty-<ver>-macos-<arch>.app.tar.gz` and `.tar.gz` |

CI also runs `cargo test --workspace` on every runner and repeats the
renderer backend tests with the native feature (`--features dx` on Windows,
`--features metal` on macOS). It does not launch the GUI and does not create
GitHub releases.

## Notes

- Compile-only checks do not exercise runtime windowing, packaging or GPU devices.
- Android requires an NDK plus an `android-activity` entry before an APK can be built.
- Local macOS checks do not prove Metal works at runtime; the native macOS CI job compiles and unit-tests the Metal build but does not run the GUI.
- Local Windows checks do not prove Direct3D 12 works at runtime; the native Windows CI job compiles and unit-tests the DX12 build but does not run the GUI.
- Windows GNU checks need a mingw linker only for linking; no Windows runtime test was performed here.
